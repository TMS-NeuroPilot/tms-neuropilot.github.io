Settings model#

Settings live in four layers. This page states which one wins, which file to edit for a given change, and what needs a restart.

The chain#

text
shell environment  >  .env (repository root)  >  ~/.neuropilot/lab.yaml  >  built-in defaults
  1. Shell environment — anything exported before the process starts. Highest priority; useful for one-off runs: RELAY_PORT=5100 neuropilot sim.
  2. .env — the repository-root bootstrap file. It is loaded once by neuropilot.config before any component imports, and it can pin any lab key, which is why an existing installation keeps behaving as before.
  3. Lab profile — ~/.neuropilot/lab.yaml, edited in Config › Lab (NEUROPILOT_LAB_FILE moves it). It is exported with os.environ.setdefault, so it only fills keys the shell and .env left unset.
  4. Built-in defaults — the values in lab_profile.DEFAULTS and the _env() calls in neuropilot/config.py.

The two session layers#

The study profile and the project file are not overrides of the chain. They are data that the GUI applies to the live controls:

Layer Edited in Applies
study profileConfig › Studyon Apply to session; MEP windows and channel names on restart
project fileProject pageon Load

A value that .env pins is still the value after a restart, even if a study profile set something else at runtime.

Which file should I edit?#

Ask one question:

Question Scope Where
Would another lab need a different value?Lablab.yaml (Config › Lab)
Would another study need a different value?Studystudy YAML (Config › Study)
Would another subject need a different value?Subjectproject YAML
Is it a simulated-MEP tuning value?Simulation.env (Config › Simulation)
Must the value exist before the GUI starts?bootstrap.env

Examples:

  • relay address, serial ports, EMG credentials, theme → Lab
  • fit function, ISI, amplitude, MEP windows, channel names → Study
  • mesh, ROI, library, placements, results path → Subject
  • simulated MEP noise, threshold, upper limit, E-field scale (dI/dt) → Simulation
  • data folder, readiness timeout, GLFW library, "run the GUI at all" → .env

What needs a restart#

Change Restart? Why
any .env valueyes.env is read once at import
lab relay, data folder, UI scaleyesread at start
lab robot modelyesthe simulator builds the scene at start
lab solver/anisotropynoread when the online solver loads
lab stimulator/EMG portsyesread when the systems connect
themenoapplied live and saved
study mapping/stimulation valuesnoApply to session
study MEP windows, channel namesyesread at import by the controller

Overrides are visible#

Config › Lab marks a field that .env pins (tooltip) and counts them in the status line:

text
Loaded lab.yaml (~/.neuropilot/lab.yaml) · 3 key(s) overridden by .env

If a value you just typed does not survive a restart, this line is the reason.

Why .env stays the top file#

Two practical reasons:

  • Bootstrap keys must be readable before the GUI exists: ROOT_FOLDER, RELAY_PORT, READINESS_TIMEOUT_S, PYGLFW_LIBRARY, ENABLE_HEALTH_CHECK_AND_CONTROL_PANEL.
  • Pinning lets a lab freeze a value without granting edit rights to ~/.neuropilot/lab.yaml, and lets CI override everything from the environment.

The lab profile is portable#

lab.yaml contains only the keys in LAB_KEYS and is written with a header that restates the precedence. Unknown keys are preserved when the GUI writes the file, so hand-written comments and extra keys survive an edit.
