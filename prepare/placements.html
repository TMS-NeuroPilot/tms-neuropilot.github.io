Coil placements and target order#

The placements file says where the coil can go. The target-order file says where it goes next. Both are index-aligned with the E-field library, which is what keeps the regression consistent.

The placements file#

search_positions.hdf5 from SimNIBS TMSoptimize (or the group's wrapper):

Dataset Shape Meaning
matsimnibs(4, 4, n) floatone coil matrix per placement, mm, SimNIBS space
centers(n, 3) float, optionalcoil centre per placement
m0, m1, m2(n, 3) float, optionalcoil axes, for inspection

The controller reads only matsimnibs. Each matrix follows the convention in Units and frames: translation is the stimulation point, rotation columns are the coil axes.

⚠Order is meaning

Row i of matsimnibs is column i of E_mag. If you sort, subsample or filter the placements, you must apply the same reordering to the E-field library. sort_coil_placements.py exists for exactly this reason — see below.

The target-order file#

A plain text file with one integer per line:

text
44
477
391
156
22

Rules:

  • indices into the placements file, 0-based (the first placement is 0);
  • one target per line; whitespace and blank lines are fine;
  • values must be integers and 0 <= index < n_placements;
  • the file is validated when you load it, not when you press Start.

An invalid file is rejected with a message naming the offending index:

text
Target order ernie.txt references target 500, but only 500 placements exist.

If you do not load an order file, the controller stimulates all placements in file order — useful for a first test, slow for a real session.

💡Repeats are allowed

The order file may repeat an index. A protocol that alternates between two hot spots, or returns to the best target at the end, is just a longer list.

Choosing an order#

scripts/03_create_optimized_sequences.py selects a subset of placements that constrains the regression well and writes an order file:

bash
python scripts/03_create_optimized_sequences.py \
    --e-hdf5 data/<subj>/efield/e.hdf5 \
    --n-stim 200 \
    --out-dir data/<subj>/coil_path
Flag Default Meaning
--e-hdf5requiredthe E-field library to select from
--n-stim500number of pulses to plan
--out-dirnext to the librarywhere the order files are written
--seed42RNG seed for the random baseline
--datasetE_magwhich field dataset to use
--normalizenonefeature normalisation before selection
--rbf-tau, --rbf-ridgeauto, 0.0RBF kernel width / ridge for D-optimal
--w-pos, --w-ang2.0, 1.0travel cost weights (position mm, angle deg)
--no-auto-sortoffkeep the selection order instead of travel-sorting

It writes one file per strategy (RANDOM, FPS, D-Optimal, …) plus a *_travel_sorted.txt variant. Use the travel-sorted file: the robot spends most of its time moving between targets, and a spatially coherent order roughly halves the session duration.

Sorting placements for travel#

If you already have a placement file and an order, reorder both together:

bash
python scripts/sort_coil_placements.py \
    --matsimnibs data/<subj>/efield/search_positions.hdf5 \
    --coil-seq   data/<subj>/coil_path/selected.txt \
    --out-dir    data/<subj>/coil_path

The script writes a new matsimnibs file, the matching order file and an XDMF for visual inspection. Use the outputs as the project's targets_file and target_order_fn; do not mix the sorted order with the unsorted library.

Common mistakes#

Symptom Cause
references target N, but only M placements existorder file is 1-based or from another subject
contains non-integer entriesa header line, a comma-separated list or a float
every pulse uses the same fieldorder file lists one index repeatedly
map looks spatially scrambledsorted placements paired with an unsorted library
robot takes a long path between targetsraw algorithm order instead of *_travel_sorted.txt
Coil at target never arrivesplacement is outside the robot's reach or collides
