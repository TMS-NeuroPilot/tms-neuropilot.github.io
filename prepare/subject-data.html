Subject data#

A session needs five artefacts for one subject. This page says what each one is, which script produces it, and what TMS NeuroPilot checks when it loads it.

The artefacts#

Artefact File Produced by Used for
Head meshm2m_<subj>/<subj>.msh (or an HDF5 mesh)SimNIBS charmthe 3-D view, the robot's head model
ROI surfacegeo.hdf5ROI extraction from the midlayer surfacethe map: one R² per triangle
Coil placementssearch_positions.hdf5SimNIBS TMSoptimizethe targets the loop visits
E-field librarye.hdf5scripts/02_create_roi_efield_library.pyper-pulse E-field rows
Target order*.txtscripts/03_create_optimized_sequences.pywhich placement to stimulate, in which order

Two more small files complete a project: the EMG channel sources (*.yaml) and the coil model (*.ccd).

1. Head model#

TMS NeuroPilot reads the SimNIBS head mesh directly:

text
m2m_<subj>/<subj>.msh

Create it with SimNIBS charm (the group's scripts/01_create_head_model.py wraps this for a subject HDF5):

bash
python scripts/01_create_head_model.py \
    -s data/<subj>/<subj>.hdf5 \
    -m mesh_<subj>_lincc \
    --charm_ini scripts/configs/charm_410.ini

The script runs charm (segmentation + meshing) and writes the m2m_<subj> folder next to the subject's MRI. See the SimNIBS documentation for charm options; --charm_cmd_params forwards extra flags, --mesh skips segmentation when you already have one.

⚠Size

A full head mesh has 1–2 million triangles and is 150–350 MB. The 3-D view decimates it for display, but the file must stay complete for the FEM.

An HDF5 mesh with mesh/nodes/node_coord and mesh/elm/triangle_number_list is also accepted. The bundled example subject uses a SimNIBS .msh head mesh.

2. ROI surface#

The region of interest is the cortical surface patch the map is computed on. It is a triangle mesh in an HDF5 file:

Dataset Shape Meaning
mesh/nodes/node_coord(N, 3) floatvertex positions, mm, SimNIBS space
mesh/elm/triangle_number_list(M, 3) int, 0-basedtriangle vertex indices
mesh/elm/tri_tissue_type(M, 1) int, optionalper-triangle label, used for colouring

The example subject uses a midlayer surface (midlayer_m1s1pmd): a surface halfway between the grey/white boundary and the pial surface, which samples the field where the pyramidal cells sit.

ℹElement count is a contract

The number of E-field columns must equal M. If you change the ROI, every E-field library computed for the old ROI is invalid. TMS NeuroPilot reports the mismatch instead of silently using the first columns.

3. Coil model#

A SimNIBS .ccd file (optionally .ccd.nii.gz). The file defines the coil geometry used by the FEM; it does not affect where the robot moves. Use the model that matches the physical coil — a B65 model for a B65 coil.

The file dialog starts in the SimNIBS coil library (simnibs/resources/coil_models/).

4. EMG channel sources#

The channel names and count come from EMG_CHANNELS in .env. The cortical source of each channel comes from a small YAML, one entry per channel, assigned positionally:

yaml
sources:
  - element_id: 5208        # FDI: index into the ROI triangles
  - element_id: 5165        # APB
  - xyz: [-16.2, 14.6, 61.9]  # ADM: position in mm; nearest triangle is used

element_id is a 0-based index into the ROI triangles, which is also the column index in the E-field row. It must be < n_elements. xyz is projected onto the nearest ROI triangle centre; the projection distance is printed, which makes it a safe alternative when you know the anatomy but not the index.

In simulation and training, the loaded sources are also drawn as labelled spheres on the Cortical results page ROI surface.

See EMG channels and MEP windows for the full format.

5. Results file#

A path to a CSV the controller appends to during the session. It is created if missing; the folder must exist and be writable. The columns are documented in Export and data formats.

Sanity checks before the session#

Adjust the three paths, then paste this into a Python session (or save it as check_subject_data.py and run it):

python
import h5py

roi = "roi/geo.hdf5"
efield = "efield/e.hdf5"
placements = "placements.hdf5"

with h5py.File(roi) as f:
    n_elements = f["mesh/elm/triangle_number_list"].shape[0]

with h5py.File(efield) as f:
    e_mag = f["E_mag"]
    print("E_mag", e_mag.shape, "elements", e_mag.shape[1])

with h5py.File(placements) as f:
    mats = f["matsimnibs"].shape
    n_positions = mats[2] if mats[:2] == (4, 4) else mats[0]
    print("placements", n_positions)

print("ROI triangles", n_elements)
  • E_mag.shape[1] == ROI triangles
  • E_mag.shape[0] == matsimnibs.shape[2]
  • every target-order index is 0 <= i < n_placements
  • EMG_CHANNELS has as many names as the source YAML has entries
  • the mesh opens in the Cortical results page

Where the scripts live#

Script Purpose
scripts/01_create_head_model.pyrun charm, produce m2m_<subj>/<subj>.msh
scripts/02_create_roi_efield_library.pycentre the search on the ROI automatically, solve the FEM for every placement, write e.hdf5
scripts/03_create_optimized_sequences.pychoose a subset/order of placements (random, FPS, D-optimal)
scripts/sort_coil_placements.pyreorder placements for minimal robot travel
scripts/make_tissue_stls.py, msh2vtk_surf.pysurface extraction, for inspection
