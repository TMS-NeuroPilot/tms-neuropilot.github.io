About the project#

TMS NeuroPilot is research software from the Brain Networks and Neural Data Science and Statistical Computing groups at the Max Planck Institute for Human Cognitive and Brain Sciences (MPI CBS) and the Center for Scalable Data Analytics and Artificial Intelligence (ScaDS.AI), Leipzig, Germany. It runs optimized TMS mapping experiments based on per-pulse electric fields and integrates with InVesalius neuronavigation to guide TMS placements across many pulses. It performs online mapping analyses, supports robot integration, and ships a complete virtual twin to test and debug workflows without hardware or subjects.

It is not a medical device. Real stimulation needs ethics approval, a trained operator and the stimulator's own safety limits.

What it is for#

  • Run E-field-optimized mapping experiments with online analysis
  • Simulate mapping results for different optimization functions
  • Switch between precomputed E-fields and online E-field calculation
  • Put new optimization schemes to the test with a realistic virtual twin
  • Switch mapping parameters live, such as the fit function
  • Exclude single-trial responses during a run
  • Train mapping experimenters in realistic settings with simulated MEPs
  • Add new hardware setups, optimization schemes or fit functions thanks to the modular design

Scientific scope and limits#

TMS NeuroPilot implements per-pulse E-field mapping: each pulse is paired with the field at its realised coil pose, and a regression is fitted separately for each ROI element and EMG channel. This follows the element-wise mapping approach described by Numssen et al. (2021) and the TMS mapping protocol of Weise et al. (2023). Coil placement optimisation can use FPS (Schultheiss et al., 2025) or D-optimal design (Qiu et al., 2026; Numssen, Qiu et al., 2026). The interpolated E-field mode uses the surrogate method of Grosshagauer et al. (2025).

The R² map is an explanatory localisation fitted to the collected pulses. It is not a significance map, a causal source reconstruction, or a clinical diagnosis. Report it with the pulse count, excluded pulses, fit function, subsampling factor, E-field mode, coil model and registration quality. The cortical results page and analysis page state the guards that limit interpretation.

The virtual twin and the virtual EMG are models. They are useful for testing the controller, the relay protocol, the mapping loop and operator training, but they do not replace measurements of a participant's EMG or field. Real stimulation still requires ethics approval and the stimulator's own safety limits.

Components#

Component Role
neuropilot.controllerGUI, state machine, analysis, online solver
neuropilot.sim_relaysimulated Socket.IO relay
neuropilot.sim_robotMuJoCo robot twin
neuropilot.sim_navvirtual neuronavigation
InVesaliusneuronavigation: tracking, registration, markers
tms-robot-controlproduction relay (relay_server.py) and robot driver (main_loop.py)
pynibsMEP extraction, the nine fit functions, regression
SimNIBShead meshes and the online E-field solver

The four neuropilot.* packages are this repository. The sim_* packages are not a separate pipeline: they speak the same relay topics as InVesalius and tms-robot-control, so the controller does not know whether the peer on the other end is real or virtual. pynibs and SimNIBS are libraries the controller imports, not processes.

The suite has more than 800 pytest tests, including GUI tests, six-page visual baselines and a relay-topic contract test. The documentation has its own contract tests: every environment key, lab-profile key, relay topic and fit function has to be documented, or CI fails. See Testing and CI.

Contributing#

Issues are welcome on the public tracker. Pull requests are welcome too: this repository is a read-only public mirror, so they are ported upstream by hand rather than merged here. Before opening one:

bash
pytest -m "not gui" -q          # or scripts/run_tests.sh
python docs/site/build.py --check

If you change a setting, a relay topic or a fit function, add the matching row to the docs; the contract tests will tell you if you forgot. Changes to code that also exists upstream (InVesalius, tms-robot-control) must stay additive and unprefixed; see Add a component.
