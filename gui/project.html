Project page#

The Project page loads and saves the subject's YAML and shows every file the session needs. It is the first page to fill in, and the one to re-check before pressing Start.

Project card#

Control Behaviour
Project namelabel used in the title bar and as the default file name
Loadopens a YAML file; refuses non-mappings and corrupt files
Savewrites the current project; appends .yaml when the name has no extension

An unsaved change marks the title with an asterisk. Loading is refused while a mapping is running; saving is always allowed.

Each row is validated when you leave the field: a missing or malformed file is reported in the tooltip and in the log, and the path is kept so you can fix it without retyping.

Large meshes, coil placements and E-field libraries are read in the background. The row shows loading... while the read runs, the rest of the window stays usable, and Start remains disabled until the file has been applied. Changing a path starts a new read and discards the old result.

The head mesh also replaces the head phantom in the simulated robot view. Selecting or typing a mesh updates it directly; clearing the field returns the simulator to its bundled default phantom (head.stl).

💡Browse buttons

Every row's browse button opens the dialog in the folder of the current value, or in your home folder. The head-mesh dialog filters for .msh and .hdf5; the coil dialog starts in the SimNIBS coil library.

Reading the page at a glance#

  • A filled row is a file the controller has accepted, or one that is still being read in the background.
  • A message in the row tooltip or the log means the file is missing or failed validation.
  • The Results file row shows where the CSV will be written; its folder must exist. Overwrite existing file is on by default. Turn it off to keep an existing file and write the final table to a timestamped copy instead.
  • The Config › Subject tab mirrors this page read-only, with the same save/load shortcuts (see Config page).

Load semantics#

  • Only *.yaml / *.yml are offered.
  • The loader accepts a partial file: keys that are absent keep their current value.
  • Values of the wrong type are skipped with a warning; one bad key does not block the rest.
  • After a successful load the path is restored on the next start.
  • The E-field mode stored in the file is applied (if that mode is available).

Save semantics#

yaml
project_name: NP001_M1_left
mesh_head_path: /data/NP001/mesh/m2m_NP001/NP001.msh
...

The full key list, with types and defaults, is in The project file.

Symptom Cause

Start disabled after loadingno E-field library loaded in precomputed mode
paths work on your PC but not the lab PCan absolute path outside the project folder points at a location that exists only on that PC; paths below the project file are relative and portable
