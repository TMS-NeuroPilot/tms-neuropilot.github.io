Collision test#

Long coil handles and a subject who can only sit a few ways make robot-cell layout a real constraint. The Collision test page lets you find a subject position, robot base and start configuration before a real experiment, using the selected robot model in a local MuJoCo scene. It does not stimulate, record EMG, fit a map or talk to the real robot.

The page is available in every mode that has a robot. It is disabled in manual and training modes, where there is no arm to test.

What it checks#

  • the robot and coil holder against the subject head phantom;
  • robot self-collision;
  • every placement in the project's placement file, in file order;
  • the direct joint-space path from the start pose and then from one placement to the next.

It pauses at the first collision and leaves the arm at that pose, so you can see what hit. The head and robot base can then be moved, the coil raised with Move coil up, or another branch selected, and the same scan resumed. An IK failure still stops the scan because there is no colliding pose to inspect. Placements are converted with the same pipeline-to-robot axis convention as the simulated robot and then into the robot base frame, so the planned world pose and an executed target agree even after the base is moved.

Method#

The scene is compiled from the selected robot's MJCF model and the subject skin surface. MuJoCo evaluates contacts and nearest distances; ikpy solves the same URDF chain that the simulated robot uses. The scan follows the production direct-or-upward rule. It compares the largest per-axis translation with TRANSLATION_THRESHOLD (millimetres) and the largest per-axis rotation with ROTATION_THRESHOLD (degrees). If either limit is exceeded, the arm climbs to SAFE_HEIGHT (millimetres), traverses above the head and descends. Otherwise it uses a direct joint-space line. There is no separate 20 mm retract waypoint. Each segment is sampled at 30 waypoints and every waypoint is checked. The same three values are also used by the manual move-away and emergency paths, where the arm always climbs to SAFE_HEIGHT.

A head penetration of 4 mm or more and a self-penetration of 2 mm or more count as collisions. The 4 mm head allowance matches the production simulation, where the coil is pressed into the scalp. Head clearance of 10 mm or less is not reported as a near miss, because the coil is often close to the scalp; the always-on contact-colour overlay shows that clearance on the links.

Self-collision ignores overlaps shallower than 2 mm. The robot's collision meshes overlap by about 1 mm at some wrist configurations even though the rendered links look clear, so these shallow self-contacts are treated as mesh overlap. A self-penetration of 2 mm or more still pauses the scan. This tolerance is a modelling limit, not a hardware safety margin.

MuJoCo is described in Todorov, Erez and Tassa (2012), MuJoCo: A physics engine for model-based control, IEEE/RSJ International Conference on Intelligent Robots and Systems. ikpy is a pure-Python inverse-kinematics library built on the URDF joint chain.

⛔Safety: planning aid, not a certificate

The scene contains the head phantom only. It does not model the subject's shoulders, torso, chair or the room. The path is a joint-space interpolation, not the production controller's exact trajectory. The real robot controller and its force/safety limits remain the final authority.

Enable it#

Press Enable collision test. The first enable builds the local world and IK chain; later scans reuse it. The page also loads the project head mesh and converts its skin surface to an STL, so the phantom matches the subject.

The 3D view uses the same embedded renderer as the simulated robot view. Drag to orbit, right-drag to pan, wheel to zoom, double click to reset. Its top-right overlay mirrors the Control page: Total targets and Current show the same pulse 0 · 1/1 · target 44 counters. The path waypoint is in the status line below the scan controls. The collision test checks the target geometry; it does not fire stimulation pulses.

Position the subject and robot#

Control Unit Meaning
Robot basemm, degWhere the robot stands in the room and how it is rotated
Subject placementmm, degWhere the SimNIBS head origin sits relative to the robot base

Each row has −/+ buttons for a small nudge. Changing either pose resets the arm to the stored start configuration and updates the collision label.

The head and robot base are relative descriptions of the tested cell. They do not move the real robot base; they record the arrangement you validated.

Jog the coil#

The jog pad moves the coil site in world XYZ and rotates about the tool axes. The numbers beside the axis names show the current coil-site pose in world millimetres and tool degrees. The IK solver converts each request to joint angles and rejects a target it cannot reach; the status line says when a jog failed.

Use a small step for final placement. A red COLLISION or amber NEAR MISS label updates after every jog.

Cobot pose setting#

Three radio groups choose the IK branch. Every option stays visible, so a branch never depends on a dropdown popup:

  • Shoulder left or Shoulder right, the sign of the first active joint;
  • Arm up or Arm down, the sign of the third active joint;
  • Wrist normal or Wrist flipped, the sign of the fifth active joint.

The elbow boundary is inclusive: a straight arm has zero on the third joint and is the Omron arm-up pose. The simulator's power-on configuration is the same zero joint pose, and the collision test starts from that pose as well. A new setup defaults to shoulder right, arm up, wrist normal; a branch saved in the project or lab profile still wins for that setup. The wrist sign is evaluated on the canonical joint angle in [-180°, 180°], not on an arbitrary 360° representation. This keeps normal and flipped physically distinct instead of showing the same pose twice.

A 6R arm can have up to eight IK solutions. Some are unreachable because of joint limits or collisions. Press Set start pose from selection to solve the chosen branch for the coil pose the robot currently holds. The coil placement stays fixed; only the arm configuration changes. If only a colliding solution exists, it still stores that pose and warns you to adjust the base/head before scanning. If no solution exists, it leaves the current pose untouched, keeps your radio selection, and asks you to jog to another pose. The resulting six joints become the start configuration and are sent to the Control page, so both pages show the same cobot pose. Move coil up moves the local arm to the configured safe Z while keeping the coil orientation; it does not change the stored start pose.

Movement limits#

The compact row under Cobot pose setting exposes the three values that decide between a direct move and the safe-height path. They are also shown on Config › Lab under Cobot pose:

Field .env key Unit Meaning
Safe ZSAFE_HEIGHTmmZ above the robot base that the arm climbs to before traversing
Translation thresh.TRANSLATION_THRESHOLDmmLargest per-axis translation that still allows a direct move
Rotation thresh.ROTATION_THRESHOLDdegLargest per-axis rotation that still allows a direct move

The fields start from the .env values in neuropilot/.env, the project collision block, or the lab collision block, in that order. They can be changed while a scan is running: the current target is replanned from the arm's present pose and the completed pulses stay in place. The values are stored in the project and lab collision blocks when Make project default or Make lab default is pressed. They are sent to the simulated robot on Pipeline to Robot: Set motion limits at the next experiment start. The names and units match tms-robot-control/.env; the production controller must handle the topic before it can apply project values without an .env restart.

Run the scan#

  1. Load the project's placement file on the Project page.
  2. Choose a cobot pose and, if needed, adjust the movement limits.
  3. Press Start collision scan. The button becomes Pause collision scan while the scan runs; press it again to resume.
  4. Use Prev target and Next target around Stop to change the current target without restarting the scan.
  5. Set Movement speed in the row below the progress bar. It is linked to Default speed on the Control page and changes both the scan playback pace and the simulated experiment speed.
  6. The contact-colour overlay is always on. Green marks the outer near band, orange is halfway, red is close to contact and dark red is actual contact. A self-collision tints both involved links, and a head contact tints the head mesh.

The scan follows the project's target-order file and repetition count, so its pulse numbers and target IDs match the Control page. Without an order file it uses every placement in file order. The progress bar counts reached pulses. Pause collision scan stops the timer but keeps the current path, target and completed results; the same button resumes. On a collision the scan pauses instead of ending, the message names the pulse and target, and the arm stays at the colliding waypoint. Move the coil up or change the base/head, then press Resume collision scan. The current target is replanned from the new pose.

The robot base and subject placement can be changed while a scan is running. The scan continues from the current pulse, regenerates the remaining target poses from the new layout and replans the current target from the arm's present pose. It does not restart at pulse zero. The progress bar keeps the pulses already completed.

Head proximity within the 10 mm band is not reported as a near miss: the coil is often close to the scalp. The always-on contact-colour overlay shows clearance on the visible link meshes instead. Transparent collision hulls stay hidden, and links outside the band keep their original colour. The collision line keeps a previous collision visible after the current pose becomes clear, and the completed summary reports any collision pauses that were resolved.

An IK failure is not a collision. It means the selected shoulder, arm and wrist branch cannot reach that target from the previous pose. The scan keeps the chosen branch for every target and every safe-height waypoint; it never substitutes another arm shape. If a waypoint or target has no solution in that branch, the scan stops, leaves the arm at the last reached target, and says that the selected branch has no IK solution. This is the behaviour the simulated experiment uses when the start pose carries the same branch. The same decision is shown on the Config page and can be saved there with the lab profile.

Save and use the result#

Button Effect
Make project defaultStores head pose, robot base, cobot pose, branch, safe Z and movement limits in the project YAML
Make lab defaultStores the same block in ~/.neuropilot/lab.yaml for projects that do not override it
Use at start poseQueues the six-joint start pose and its branch for the next experiment start

The project value wins over the lab default. The start pose and branch are sent on Pipeline to Robot: Set start pose; the simulated planner then solves every target and path waypoint in the same branch. The production tms-robot-control driver must handle that topic before a real run can use it. The head and base values are the validated cell description and remain part of the project record.

What is not modelled yet#

  • subject shoulders, torso, chair and table;
  • the production controller's exact blend, force-control and press trajectory;
  • cable routing and the robot's real joint limits beyond the URDF model;
  • link 3 against link 5 self-contact, because MuJoCo convexifies mesh geoms and the convex hull of the forearm fills the wrist fork; the visual meshes have about 15 mm clearance in the folded pose that used to report a collision.

Use the page to eliminate obvious bad layouts, then confirm the final cell on the real robot at low speed.
