E-field modes#

Every pulse needs an E-field. TMS NeuroPilot can draw it from three sources, and the mode can change during a session without breaking the regression. The third source — a surrogate interpolator (Grosshagauer et al., 2025) — is described at the end of this page.

Precomputed#

The field for every placement was solved before the session (E-field library). At pulse time the controller looks up the row of the planned placement:

text
e_matrix[target_index]  →  one row of E_mag  →  regression
  • Ready immediately.
  • Requires e_field_path and targets_file in the project.
  • The coil must actually be at the planned placement for the row to be true; the controller flags a large aim error in the log and in the export.
  • The CSV records e_field_mode = precomputed for those pulses.

Online#

The field is solved for the realised coil pose while the session runs, using SimNIBS through OnlineFEMManager:

text
realised pose  →  OnlineFEMManager  →  one field vector  →  regression
  • The solver loads once at the start: about one minute.
  • Needs the .msh head mesh, the ROI surface and the coil model.
  • Does not need the E-field library or the placements library, though a target-order file still helps.
  • Solver settings come from Config › Lab › E-field solver:
Setting Values Default
Solverpardiso (fast) or amg (robust, slower)pardiso
Anisotropyscalar or vector (needs a DTI tensor in the mesh)scalar
  • The CSV records e_field_mode = online for those pulses.

Interpolated#

The third source interpolates the field instead of solving it. The method — an a-priori simulation of the pose range around the target, then SE(3) interpolation of the field for the realised coil pose — was introduced by Grosshagauer et al., 2025, with code in the EfieldInterpolation repository (Michael Woletz and Sarah Grosshagauer). Interpolation answers in a fraction of a millisecond per pulse; the a-priori simulation is the dense-library run described in E-field library.

The mode is the Interpolated radio on the Project page. It needs:

  • the dense library (surrogate_library_path in the project), and
  • the ROI surface (mesh_RIO_path) — the library is verified against it before use: the generator stores an roi_hash over the ROI centroid sequence, and a mismatch means the field columns would not match the map.

The library loads in the background (a few seconds); pulses are held until it is ready. At pulse time SurrogateManager scales the library field (generated at 1 A/µs) by the applied amplitude — the same one-row-per-pulse contract as the other sources, so modes can be mixed within a session.

The outside policy is skip and exclude: a pose outside the trained grid is recorded with an all-NaN field row, so the pulse indices stay aligned, and the regression drops it exactly like a pulse without a field. The log says so once per excursion. There is no interpolation outside the domain, and no fallback to the online solver. The CSV records e_field_mode = surrogate for these pulses.

TMS NeuroPilot implements the estimator independently of that repository (EFieldSurrogate). scripts/03_validate_efield_surrogate.py measures the accuracy on held-out placements, scripts/04_export_efield_vtk_series.py writes FEM-versus-surrogate time series for ParaView. On the ernie phantom (20 mm / 4 mm library) a new position is reproduced to ~1.5 % field error and ~5° direction error.

Changing the stimulator output between pulses#

The MSO slider is not locked during a session. The controller snapshots the value when the pulse fires (stimulator_amplitude_at_stim) and all three sources use that snapshot:

Source Scaling at pulse time
Precomputede_matrix[target] * amplitude * 1.4
OnlinedI/dt = amplitude * 1.4 * 1e6 A/s before the FEM solve
Interpolatedunit library field * amplitude * 1.4

The scaled row is stored with the pulse. Moving the slider after the pulse does not change that row, and the next pulse uses the new value. The results CSV intensity column is the same snapshot, so a row can always be traced back to the MSO that produced its MEP.

Switching mid-run#

The mode is not locked during a session. Every pulse stores the field it was stimulated with, so switching only affects the following pulses:

  1. The regression matrix is assembled from the per-pulse rows (pulse_e_fields), not from the library directly.
  2. A pulse with a missing field is dropped, and the MEP history is re-indexed with it, so the remaining rows stay aligned.
  3. The export records the source per pulse (e_field_mode), which makes a mixed session auditable.

What happens on a switch:

  • Precomputed → Online: the solver starts loading. The coil stays on target and the pulse is held until the solver is ready; the log says Online solver ready, stimulation resumes. Switching back releases the pulse immediately.
  • Precomputed/Online → Interpolated: the library starts loading (a few seconds); pulses are held the same way. A pose outside the trained grid is not held — it is recorded without a field and left out of the map.
  • Online/Interpolated → Precomputed: immediate; no solver state is needed.

⚠Warm the solver before the subject is positioned

The first switch to online costs about a minute during which no pulse can fire. Do it during setup, not between two targets with the coil on the head.

Which mode to use#

Situation Recommendation
Library exists and the coil reliably reaches the planned poseprecomputed
No library yet, or the head moved since it was computedonline
Many pulses, session time is tightprecomputed
Dense library exists and the pose stays inside the trained gridinterpolated
The interesting question is the field of the realised poseonline
Debugging the stimulator/EMG onlyeither; precomputed is faster to start

What the analysis sees#

Both modes produce the same structure:

python
pulse_e_fields = [row_0, row_1, row_2, ...]   # one vector per pulse
pulse_modes    = ["precomputed", "online", "surrogate", ...]

assemble_analysis_matrix() drops the None rows and returns the indices it kept, which is why an aborted pulse never shifts the MEP history.

The project file remembers#

efield_mode is written into the project YAML, so a subject resumed later opens in the same mode. It is one of the few live controls that travel with the subject; the amplitude and repetitions do too.
